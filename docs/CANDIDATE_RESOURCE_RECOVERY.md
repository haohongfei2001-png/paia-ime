## Fixed source and command contract

The actual candidate bundle declares `paia-public-candidate-v2`. Its verified bundled manifest anchors the source policy before a catalog can be read. The offline bundled `paia-resources candidate-publish <baseline|updated> <expected-revision> <create|existing> <explicit-parent>` command accepts only two application-owned presets. It has no incoming pack, YAML, source digest, executable or allowlist argument. The baseline is unchanged. The update replaces the single authored `呢 / ni` row with `离线更新🧭 / li xian geng xin`; recipes, conversion maps, the original A1 proof schema and row count remain unchanged. A private helper compiles this exact source; separate native probes verify the entire existing 32-policy smoke and eight discriminating positive/eight exhaustive negative marker cases. The publisher never initializes the main engine.

The [fixed update inventory](../Resources/candidate-update-contract.json) records exact row bytes/hashes, authored input hashes and the unchanged baseline license inventory. Each native run preserves both complete public manifests. Source hashes admit these finite source identities. They do **not** authenticate opaque compiled artifacts or defend coherent same-user modification of an unsigned bundle/catalog. The new marker probe specifically rejects updated source metadata paired with baseline compiled artifacts even when the old 32-policy smoke passes. A finite behavior probe is not general artifact authentication or a language-quality benchmark. No external corpus/license claim changes.

## Public catalog, separate from personal authority

The fixed `paia-ime-public-resources` sibling belongs beside, never inside, the closed `paia-ime` settings/personal/expressions root. The catalog has its own private marker, existing-only writer lock, fixed directory/lock identities, immutable generations and canonical format-2 current/last-good index bound to the source contract. Full no-follow ancestor checks and held descriptors reject symlinks, path replacement, hardlinked/special authority files and unsafe permissions. It neither changes permissions nor adopts another root. Existing v1 decoders/layout remain unchanged.

Publishing requires the expected revision and a single writer. The prior last-good is the previously selected and genuinely probed generation, not a corrupt current pointer. Staged generations and index replacement have durability barriers. Once generation publication begins, any error quarantines that writer as an unknown outcome; no automatic retry occurs. Reopening explicitly inspects the recorded index. An interrupted first publication without an index is unavailable rather than silently initialized. Old generations and failed staging are retained; there is no pruning or orphan scan.

## Actual candidate startup

Normal candidate startup checks this fixed sibling under its application-support parent. A present root selects the catalog, including malformed roots. It tries only the recorded current and last-good; broken indexes or two rejected generations consume zero main native entries and never fall through to bundled/research resources. A never-created catalog uses the bundle. Complete erasure of the entire public root is indistinguishable from never enabling it; no same-user deletion/rollback authentication is claimed.

The selected public pack is copied privately and probed **before** exporting the current authoritative personal document. Personal compilation binds that selected reference and current exact bytes/revision, including deletion/no-relearn tombstones. No personal document, derived overlay or prior personal state is ever published in the public catalog. Public fallback rebuilds only the current personal layer; it cannot restore an old overlay. The existing final authority check, pre-entry public fallback for personal failure and one-main-entry limit remain intact. A failure after native entry does not try another engine in process.

Active sessions retain their exact resource snapshot, raw input, candidate references and dictionary revision while a separate publisher runs. A new independent process sees the new index. The offline API rejects same-process publication after that process has entered the engine. This is restart activation, not background/idle hot-switch qualification.

Actual executable checks use `--preflight --isolated-parent <new-authored-parent>` and return before IMKServer construction. Their Full/Simplified smoke session is explicit and does not change or save restored configuration. Production selection does not depend on a research environment flag or new management window. These commands are engineering tools, not an installer, signed updater or arbitrary package importer.
