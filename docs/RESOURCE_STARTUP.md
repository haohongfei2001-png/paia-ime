# Recoverable public fixture resources — implementation checkpoint

Original HANDOFF sections 2/4/10/11 and REPORT 10.5/13 require staged complete resources and last-good recovery. This node implements the **startup-only subset**, not live hot switching, a signed downloader, installed recovery or production vocabulary.

The closed authored preset reproduces the three A1 inputs byte-for-byte, adds a second independent schema sharing that tiny dictionary, and offers an explicit extended test preset with one authored update row. Sources, complete schema/artifact graph, ABI/header/engine digest and provenance are fixed by application code. Incoming manifests cannot omit a required second schema. No custom YAML/Lua/plugin/package importer exists. The default unsigned uninstalled bundle packages only these precompiled fixture artifacts and its authored helper, never the research corpus or personal data.

`paia-resources` compiles the trusted preset in an isolated process, then a separate no-deploy engine process verifies every schema through raw input, real candidate selection, one reservation/commit and drained commit. Publication uses one locked, canonical index containing current and last-good references. The new last-good is the previous **verified** selection, not a potentially corrupt current. Files are copied through bounded descriptor-relative regular-file reads, with size/digest/name/complete-graph checks. Published generations are not overwritten or pruned. Interrupted staging may remain unreferenced; startup ignores it.

The index rename is the publication boundary. Any error after attempting it leaves the writer quarantined as durability-unknown; there is no implicit retry. Both generation directories remain. A new independent read verifies what is actually present. Initial root, generation and index directory entries have explicit flush barriers; these are tested OS acknowledgements, not a promise against every storage hardware failure.

Read-only startup verifies and privately copies current, probes its exact verified artifact bytes in a child, reverifies the private pack, then enters the main runtime once. On static/probe/crash/timeout/receipt failure it tries the one recorded last-good before main entry. If neither is qualified, it fails before main initialization. A later main-engine error consumes that process's attempt and never triggers in-process fallback. A killed child is reaped before fallback; its temporary trees live beneath parent-owned scratch. This does not pretend that a Swift timeout interrupts C++ or promise that an OS-uninterruptible process always terminates within a wall-clock bound.

The new C entry skips deployer initialization, schema deployment and maintenance; further named deployment is disabled in precompiled mode. The existing explicit A1/A2/B lab paths still compile separately. Service lane selection is based on its declared application contract, not resource-file existence, so a missing bundle pack cannot silently fall back into compilation. An explicitly selected public store and research/personal engine flags are mutually exclusive. `PAIA_RESOURCE_ROOT` is an explicit developer experiment, not background profile discovery.

The ordinary dispatcher/session owner is unchanged. Existing composing processes retain their immutable resource snapshot; an offline publication cannot hot-switch or replay their input. The next independent startup selects the new generation. Public packs do not contain or recover LexiconStore, ExpressionStore, SettingsStore, personal-derived schemas or engine userdb. Testing a public rollback alongside unchanged synthetic tombstones does not qualify a future combined personal-overlay migration.

## Evidence status

Initial source checkpoint: static pin/privacy, C syntax, Python, shell, YAML and diff checks pass on Linux. **Swift compilation and all new native execution are pending** at this checkpoint. Nine ResourceCore tests use synthetic binary bytes and are only SIMULATED. The official existing macos-15 IMK workflow adds real compiler/probe, seven independent startup stages, helper fault isolation, all-schema failure and missing-bundle preflight. Previous green CI is not attributed to these changes. Complete failed and skipped stages will remain in the acceptance records.

Required native acceptance includes actual artifact inventory (schema/table/prism/reverse), zero deployment counters plus private user-directory inspection, current/update/fallback/semantic-corruption real IMK commits, corrupt-both zero main entries, late failure single main attempt, active-composition immutability and next-process activation. First compiled bytes are hashed; reproducible compilation is not presumed.

## Remaining trust and product gates

Unsigned hashes link integrity; they are not publisher authentication, a license grant or protection against a same-user attacker rewriting the whole store/application. Input and binary parsing still depends on the fixed upstream engine. A successful helper probe does not guarantee a later main process cannot fail. Actual release code needs signed packages/application identity, licensed production resources, background preparation and verified idle activation/migration/rollback, installation and real-host acceptance. Fixture provenance retains the A1 no-general-license/production-model limitation. No signing credentials, installation/registration, normal IMKServer start, network, paid resource or private input is used here.
