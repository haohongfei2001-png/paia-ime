# Explicit bounded context and reviewed edits

Status: uninstalled, authored-client-qualified implementation. Native evidence is commit-bound in [the checkpoint record](../evidence/imk-context/VALIDATION.md); current acceptance is on [PR #15](https://github.com/haohongfei2001-png/paia-ime/pull/15). This is not a live-client compatibility claim. This is the original HANDOFF §6 C2/C3 capability slice plus contextual known-character entry, not a new manager or model service.

The production controller constructs the default `IMKTextInputBridge` without a qualification provider. Its advanced menu items are disabled. Protocol conformance, bundle identifiers, selector presence, a stable length or a successful read never grant capabilities. Current tests alone inject an authored adapter contract: separate read/replacement permission, permission epoch, document revision and explicitly cost-qualified length metadata. The synthetic revision observes its NSTextStorage edits. Actual external clients have no such qualification yet; public IMK alone does not promise cheap length, revision, stable document identity or atomic replacement.

An explicit menu capture reads at most 1024 selected UTF-16 units, a 256-unit left and 128-unit right neighborhood, with at most one unit of surrogate adjustment at each side. Overlarge selections are rejected, never silently truncated. The Objective-C shim copies bounded raw NSString UTF-16 before Swift String conversion; malformed surrogates, missing/oversized actualRange, count mismatch and unproven boundaries fail closed. Only document start or a retained-left LF provides a conservative segmentation reset. The right endpoint needs an observed following scalar or the qualified document endpoint. Long combining/ZWJ/RI chains without sufficient evidence are refused, not scanned further. Both original selection and replacement joins must be grapheme boundaries, including empty deletion and known-scalar insertion.

Capture creates a one-shot context-review-only idle InputSession. Ordinary key/candidate/expression/retained-repair entry points cannot use it. Cancel, finish, deactivate, close, permission revocation and target invalidation retire it. A non-key panel holds a bounded in-memory literal draft; it does not compose Chinese Pinyin. No clipboard read, model request, persistent context, automatic learning or host mark occurs. Draft key editing and presentation use captured values and geometry without document getters. Return opens full original/replacement review; a separate nonrepeated Return or Apply accepts. Every draft edit retires the previous preview token. Known-character input is an explicit U+ scalar identifier; it is not character discovery or a glyph-availability promise.

Each explicit validation observes fixed bounded reads, selected/marked range, length, permission epoch and revision with reentry checks. Full unit-exact source evidence is compared, not canonical String equality. C2-only capture cannot apply. A C3 Apply consumes its presentation identity before host callbacks, creates a reviewedEdit effect with exact UTF-16 replacement range (including real empty deletion), then uses the existing SessionCore reservation and IMK coordinator apply dispatcher. Post-write verification checks the shifted right neighborhood, expected new length/caret and unchanged permissions. An unknown result preserves original/issued text in volatile recovery, retires the owner, and never automatically retries, undoes or clears text.

Repeated observations are not cross-process CAS. Qualified revision must actually track the relevant document lifecycle; equal lengths or finite neighborhoods alone cannot detect every same-content target swap, distant edit or ABA. No automatic upgrades or live-app allowlist is introduced. The original C0 path continues zero document-length queries. Installed compatibility, privacy/sensitive-field qualification, general Chinese manual rewrite composition, production corpus permission, language quality, visible latency, physical input and release remain open.

CI reuses the existing `imk-integration.yml` macos-15 workflow, original pinned A1 engine and authored fixture. The new ContextCoreTests and ContextIMKTests retain actualRange/malformed UTF-16/Unicode refusal, separate capabilities, stale/duplicate/reentrant/unknown-result cases and actual non-key full-review renders. Test counters and screenshots must be read from actual final/exact-main runs before marking this node accepted. ENGINE_NATIVE and APPKIT_HOST evidence does not imply INSTALLED_IME, LIVE_CLIENT or HUMAN_STUDY.

## Protocol and boundary sources

The workflow retains the actual Apple SDK IMKInputSession.h used to compile: stringFromRange:actualRange: is document-relative and reports surrogate adjustments; length may be expensive and must not be polled; attributesForCharacterIndex: is inline-relative and uses zero while idle. The contextual capture uses idle zero, and existing C0 candidate placement uses its owned mark's relative caret. Merely checking a returned numeric length cap cannot bound a blocking call; only the explicitly qualified synthetic adapter is enabled here. A successful capture makes four bounded text reads and six cheap length observations, explicit review two and three, and Apply four and six including readback. Draft keys, menu construction and rendering make none. These fixed observations are not cancellation of a blocked client call.

The conservative LF/document-start reset and join tests are motivated by [Unicode UAX #29, revision 47](https://www.unicode.org/reports/tr29/tr29-47.html#Grapheme_Cluster_Boundary_Rules). The implementation uses the actual Swift runtime's Character segmentation, with toolchain version retained per run; it does not claim an exhaustive Unicode conformance suite or normalize selected text. Long context with no proven reset remains unsupported rather than being granted speculative boundaries.

That failed run's later research/basic/repair stages were skipped, not passed; its successful render test is not a completed evidence claim because serialization after the failed suite did not run. Full original failure logs/artifact metadata are retained in the recovery package. Every revised source, including final presentation reentry hardening, requires its own native CI; previous success is never inherited.

Native presentation builds new offscreen text/scroll views for each render. A presentation generation is assigned before the first reentrant current-target query; every publication/window step rechecks it. A delayed old render cannot overwrite the newer review's shared text or hide its window. Native tests exercise all five such callback points. This protects presentation identity; physical focus and installed-client behavior still need live verification.
